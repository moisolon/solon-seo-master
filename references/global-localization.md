# Global operating rules

Read for every engagement. Worldwide usability is adaptation, not an assertion that every search engine, law or language tool is available.

## Market and language matrix

Record each target market, audience language/script, existing URL prefix/domain, search intent, important search engines, report language and evidence source. Infer from explicit instructions and site content, confirm ambiguities that would change publication. Do not default to Brazil, Portuguese, English or the agent's machine location.

Research actual queries in the audience's language and location. Account for regional synonyms, dialects, transliteration, morphology, local terminology, units, currencies and date/number conventions. Do not translate a keyword list mechanically or invent volume when local data is unavailable. Google and Bing are core checks; add regional engines when relevant and supported, recording access limitations. Do not promise universal market coverage from a single global search session.

For each locale: choose a primary intent, an appropriate existing destination or genuine content gap, and the local user task. Compare relevant local results. A different spelling, municipality or inflection does not automatically justify a separate article.

## International implementation

Use correct language identifiers for the supported platform; HTML `lang`, translation quality and audience consistency matter for usability. For Google alternate versions, validate supported `hreflang` language/optional region values, absolute URLs, reciprocal/self references and working destinations. Use `x-default` when a fallback is appropriate; do not apply it blindly. Maintain a coherent canonical strategy for each localized version instead of canonicalizing all translations to one language. See the official [localized versions guide](https://developers.google.com/search/docs/specialty/international/localized-versions).

Test locale selectors and discoverable links. Avoid forcing IP/language redirects that prevent discovery or make versions inaccessible. Validate language-specific navigation, search, breadcrumbs, sitemap and metadata. A single-language site can correctly have no `hreflang`.

Preserve Unicode in UTF-8, native scripts, meaningful text anchors and valid URL encoding. Unicode URLs are not inherently defective; do not transliterate or change live URLs merely for aesthetics. Test RTL/bidirectional text, punctuation, numerals, mobile layout and screen-reader language when relevant. Localize alt text and structured visible values; preserve stable entity IDs as appropriate.

Use fluent publication-quality language. If competence, reliable research or specialist review is missing, identify that limit and hold the affected publication in a finished draft until adequate review; continue other authorized fixes. Do not claim native review without evidence.

## Local businesses, trust and privacy

Assess eligibility for profiles/directories in each market, accurate business names, local contact/address/service-area conventions, opening hours and genuine reviews. A directory list suitable for one country is not mandatory worldwide. Avoid fake offices or review incentives that violate platform rules.

Use the actual legal identity and relevant trust information when appropriate. A Brazilian CNPJ is not a global SEO requirement. Route jurisdiction-specific privacy, consent, tracking, ecommerce disclosures and regulated content to the site's applicable policy or qualified reviewer. Do not treat a privacy-page link as proof of compliance. Analytics tooling must suit the site's consent choices and local obligations, without being compulsory for search inclusion.

## Report localization

Write recommendations in the requested language; retain diagnostic codes, URLs and relevant native query strings. Record test location, interface language, time zone, device, search surface and personalization where known. Preserve source time zones in exported metrics and normalize comparisons explicitly. Never compare mixed countries/languages as though they were one uniform SERP.
