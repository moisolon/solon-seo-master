# Evergreen SEO article lifecycle — mandatory for every publication

This applies to every language, market and SEO article created or published by this skill. Evergreen means durable user value with maintainable facts, not never needing an update.

## 1. Prove the gap and choose a durable topic

Map audience task, intent, market, language, existing URLs, commercial relevance and search evidence. Improve an existing relevant page if it already satisfies the task. Identify duplication/cannibalization before creating another URL. Lack of a blog alone does not prove an article gap; avoid unsolicited mass publishing.

Prefer enduring explanations, how-to guidance, decision frameworks, stable comparisons, troubleshooting and real documented case methodology. Avoid news, transient announcements, trend recaps, event coverage, seasonal campaigns or “best tools this week” as SEO articles. For a topical request that cannot be made evergreen without changing meaning, prepare a durable alternative and state the conflict before publication.

Do not put a year in title/slug merely to attract clicks; a historical date genuinely central to an enduring topic is different. A durable comparison can include current prices/features only with verified sources, explicit context and maintenance ownership. If volatile facts dominate the article or cannot be maintained, choose a more durable angle. No fake freshness, year-swapping, fabricated statistics or claims that an article can never age.

For topic difficulty/opportunity, consult [authority and backlinks](authority-and-backlinks.md): compare relevant SERP domains using DA, DR and Authority Score where available, plus page-level relevance and evidence. A low score does not bar publication; a high competitor score does not determine the outcome.

## 2. Build an editorial brief

Record: topic ID, target locale/script, user task, primary query cluster, existing-page decision, proposed stable URL, unique contribution, intended reader, outline, reliable sources and access dates, actual author/reviewer, conversion path, internal links, suitable visuals, maintenance owner/trigger and publication authority. Mark unknown keyword metrics as unavailable.

Keep length and structure proportional to the task. No fixed keyword density, title length, number of FAQs, minimum words or “AI answer paragraph” formula. Use headings, direct explanations, tables/examples or questions when they help people. Do not copy competitors or manufacture personal experience.

## 3. Produce and implement

Write original content in the audience's language. Explain scope, actionable steps, limitations and criteria behind recommendations. Use primary sources for technical or consequential claims; distinguish the business's own claims from independent evidence. Cite actual sources and use only real cases/credentials. If specialist verification is necessary and missing, hold that article for review while completing unrelated work.

Use a descriptive title, coherent main heading/sections, accurate description and stable canonical route. Link useful relevant service/category pages and related content naturally; external references are chosen for evidence and relevance, not only a high domain score. Use licensed or authorized media with purpose-appropriate alt text, responsive dimensions and loading behavior. Add applicable Article/BlogPosting and entity metadata only when it matches visible information; no universal schema/citation guarantee.

When translations are needed, localize intent, examples, units and internal destinations; verify each locale instead of duplicating a mechanical translation. Link language versions correctly. Do not create city variants that only swap the location name.

## 4. Publication gate

Every item must pass or have a justified non-applicability. A failed mandatory criterion blocks that article, not every independent repair.

- [ ] Topic addresses a durable need and has value beyond a temporary announcement.
- [ ] Title and stable URL do not depend on an unnecessary year/event/promotion.
- [ ] Volatile facts are verified, contextualized and maintainable; sources exist and support the claims.
- [ ] There is genuine usefulness/original contribution and no duplicate-intent conflict left unresolved.
- [ ] Language/script, local examples and business facts are correct; review limitations are addressed.
- [ ] Author/reviewer/experience are truthful; no invented customer story, benchmark, credential or metric.
- [ ] Content, internal/external links, media and CTA work; no placeholder/draft instructions remain in the public page.
- [ ] Rendered page, status, canonical and index directives match intent; sitemap/listing and contextual discovery work.
- [ ] Mobile reading/accessibility and affected site templates pass relevant checks.
- [ ] Publication destination/authority and rollback are established; required editorial review is satisfied.
- [ ] Maintenance owner or explicit proposed handoff, factual update triggers and next review are recorded.

## 5. Publish, verify and maintain

Use the existing site/CMS pipeline within authorization. Confirm live URL, visible final content, listing links and revision. Track later engine indexing and business performance separately. Never invent an indexing timeline or guaranteed target position.

Review when underlying product/specification/law/evidence changes, a link breaks, user questions reveal omissions or the content becomes inaccurate. Propose a cadence suitable to volatility; scheduling requires a request. Update substantively, preserve stable URLs when appropriate, and change modified dates only for real edits. Retain redirect history if a URL must move.
